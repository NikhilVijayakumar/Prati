# Requirements

Requirement packages capture intended behavior and acceptance criteria; knowledge describes durable concepts independently. Draft statements below are derived from existing documentation and require review against implementation and product decisions before being treated as an approved baseline.

- [Frontend foundations](frontend-foundations/requirement.md): scope, providers, theming, localization and prototype boundaries.
- [Knowledge and requirement traceability](knowledge-traceability/requirement.md): source disposition, requirements, specifications and evidence for the raw-document migration.

For new work, search `knowledge/index.md` first, then add or update a package with stable IDs, source links, knowledge references, scope, observable requirements, scenarios and open decisions. OpenSpec changes reference both the requirement and knowledge. Keep change-specific deltas in OpenSpec; merge approved enduring behavior into the appropriate baseline only after verification. Gherkin prose is not executable unless a runner and steps are configured.
