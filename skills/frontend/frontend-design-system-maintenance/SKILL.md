# frontend-design-system-maintenance

Inspect affected components, public exports, tests, relevant docs/raw guidance and available consumers. Reuse existing primitives and tokens where suitable. Define supported props, defaults, variants, states, controlled behavior and accessibility before an observable change. Preserve compatibility or document migration.

Verify behavior and documentation proportionately, including applicable theme and localization states. Identify consumers and visual checks that could not be exercised. Do not assume Storybook or shadcn are available. Request independent review when project policy or the user requires it.
